Deploy LingoBrain lên VPS

Chạy LingoBrain (Node.js + PostgreSQL) trên chính VPS đang chạy BookSnap, dùng chung Caddy. Chuyển luôn dữ liệu (tài khoản, tiến độ) từ Nhân Hòa sang. Mỗi lệnh ghi chạy ở đâu. Bắt đầu khi code đã push lên GitHub. Mất khoảng 30–45 phút.

Thông số của bạn

Điền vào đây, các lệnh bên dưới tự cập nhật (tô vàng). Chỉ lưu trong trình duyệt này.

Nhãn trên mỗi khối lệnh WINDOWS máy tính của bạn · SERVER phiên ssh vps (user deploy) · FILE nội dung một file.
Điều kiện trước Đã làm xong chương 1–5 của hướng dẫn VPS BookSnap: SSH bằng key (ssh vps), firewall, Docker, DuckDNS, Caddy dùng chung + mạng web. Tài liệu này chỉ thêm LingoBrain vào đó.

1Repo đã sẵn sàng

Hướng dẫn bắt đầu từ lúc code đã push lên GitHub. Repo đã có sẵn các file deploy:

FileVai trò
DockerfileNode 22 alpine, chạy bằng user node, HEALTHCHECK gọi /
compose.yml2 service: app (nối mạng web, alias lingobrain) + db Postgres 17 (mạng riêng, không mở cổng). TRUST_PROXY_HOPS=1 vì chỉ có Caddy đứng trước
.dockerignoreBỏ assets/ (109 MB sprite gốc), tests/, docs/, .git… khỏi image. Giữ tools/ để chạy seed-database.js
deploy/deploy.shpull → build (tag = commit) → backup → thay container → đợi /api/words 200 → lỗi thì quay về bản cũ

.gitattributesÉp *.sh dùng LF (máy Windows đang bật autocrlf)
Trước khi làm tiếpTrên trang GitHub của repo phải thấy compose.yml và thư mục deploy/. Chưa thấy = chưa push, server sẽ clone thiếu file.

2Clone code + file bí mật .env

Server
cd /srv/apps
git clone --depth 1  lingobrain
cd lingobrain
ls Dockerfile compose.yml deploy/
printf 'DB_PASSWORD=%s\n' "$(openssl rand -hex 24)" > .env
chmod 600 .env
mkdir -p /srv/backups/lingobrain
  • --depth 1: chỉ lấy commit mới nhất (repo có ~300 MB MP3 + sprite trong lịch sử). git pull về sau vẫn chạy bình thường.
  • Mật khẩu DB dạng hex → không cần URL-encode trong DATABASE_URL (khác lỗi @ hồi dùng Nhân Hòa).
  • Muốn đổi giọng/giới hạn TTS: thêm TTS_VOICE=…, TTS_DAILY_MAX=… vào .env.
  • Repo private → dùng deploy key (chương 10 hướng dẫn BookSnap).

3Lấy dữ liệu từ Nhân Hòa

Cần 1 file dump của DB lingoBrain. Trước tiên chạy câu này trên DB Nhân Hòa (console/SQL panel) và ghi lại kết quả để so ở chương 4:

SQL (Nhân Hòa)
SELECT version();
SELECT (SELECT count(*) FROM users) AS users, (SELECT count(*) FROM progress) AS progress;
Phiên bản PostgreSQLNếu version() ≥ 18: dừng lại, đổi image db trong compose.yml ở repo (bản 18 còn đổi đường dẫn volume) → push → trên server git pull --ff-only, rồi mới sang chương 4. Không sửa file trực tiếp trên server, nếu không deploy.sh sẽ kẹt ở bước pull.

Chọn một trong 2 cách:

Cách A: tải bản backup từ panel Nhân Hòa

Database → PostgreSQL (lingoBrain) → Backup → Backup now → tải file về, ví dụ D:\backup\lingobrain\. File có thể là .dump (định dạng custom) hoặc .sql/.sql.gz (SQL thường) — chương 4 có lệnh cho cả hai.

Cách B: dump thẳng từ VPS (khi DB bật được cổng public tạm thời)

Server
read -rs PGPASSWORD && export PGPASSWORD
docker run --rm -e PGPASSWORD postgres:17 pg_dump \
  -h HOST_PUBLIC_NHANHOA -p CONG -U sa -d lingoBrain \
  -Fc --no-owner --no-acl --exclude-table-data=tts_clips \
  > /srv/backups/lingobrain/nhanhoa.dump
unset PGPASSWORD
chmod 600 /srv/backups/lingobrain/nhanhoa.dump
ls -lh /srv/backups/lingobrain/
  • read -rs: gõ mật khẩu không hiện, không lưu vào lịch sử lệnh.
  • Dump xong tắt ngay cổng public trên Nhân Hòa.

Đưa file từ Windows lên VPS (nếu dùng cách A)

Windows
scp D:\backup\lingobrain\ten-file-backup vps:/srv/backups/lingobrain/
File dump chứa hash mật khẩu người dùngKhông gửi qua chat/email. Nạp xong thì xoá bản trên Windows (hoặc cất vào nơi mã hoá).

4Nạp dữ liệu rồi mới chạy app

Thứ tự quan trọng: chỉ bật DB → nạp dump → rồi mới chạy app. App chạy trước sẽ tự tạo bảng rỗng và tự nạp bộ từ, dễ đụng dữ liệu.

Server
cd /srv/apps/lingobrain
docker compose up -d --wait db

Nếu file là .dump

Server
docker compose exec -T db pg_restore -U lingo -d lingobrain \
  --no-owner --no-acl --clean --if-exists --exit-on-error \
  < /srv/backups/lingobrain/nhanhoa.dump

Nếu file là .sql / .sql.gz

Server
gunzip -cf /srv/backups/lingobrain/nhanhoa.sql.gz \
  | grep -vE '^(ALTER .* OWNER TO|GRANT |REVOKE )' \
  | docker compose exec -T db psql -U lingo -d lingobrain -v ON_ERROR_STOP=1 -q
  • Bỏ các lệnh gán chủ sở hữu cho user sa (không tồn tại ở VPS) → mọi bảng thuộc lingo. gunzip -cf đọc được cả file chưa nén.
  • ON_ERROR_STOP: lỗi giữa chừng thì dừng, không nạp nửa vời. Lỗi → xoá volume làm lại: docker compose down -v (chỉ làm ở bước này, khi chưa có dữ liệu thật).

So số liệu với Nhân Hòa

Server
docker compose exec db psql -U lingo -d lingobrain -c \
  "SELECT (SELECT count(*) FROM users) AS users, (SELECT count(*) FROM progress) AS progress, (SELECT count(*) FROM words) AS words;"

users, progress phải bằng đúng số ghi ở chương 3.

Chạy app

Server
bash deploy/deploy.sh
docker compose ps
docker compose logs --tail 30 app
  • Lần đầu build 1–3 phút. Kết thúc bằng deploy ok: <commit>.
  • Log phải có listening on :3000 → schema ready → deck up to date hoặc deck seeded: … words.
  • ps: cả app và db là Up … (healthy).

Server

	encode zstd gzip

  • DuckDNS tự trỏ mọi tên con về IP, không cần tạo thêm.
Windows
curl.exe -sI https://./
curl.exe -s -o NUL -w "%{http_code} %{size_download}\n" -H "Accept-Encoding: gzip" https://./api/words
curl.exe -s -o NUL -w "%{http_code}\n" https://./package.json
curl.exe -s -o NUL -w "%{http_code}\n" https://./.env
  • Lệnh 1: 200, có Strict-Transport-Security và Content-Security-Policy (chứng tỏ app nhận đúng X-Forwarded-Proto: https).
  • Lệnh 2: 200, kích thước nhỏ hơn nhiều so với 2,6 MB (đã nén).
  • Lệnh 3, 4: 404.
Server
sudo ss -tlnp | grep -v 127.0.0.

Chỉ thấy 22, 80, 443. Thấy 3000 hoặc 5432 = có cổng lọt ra ngoài, xem lại compose.yml.

  • iPhone Safari: mở trang → Thêm vào màn hình chính → tắt mạng, mở lại vẫn chạy.
  • Ôn 1 thẻ trên máy A, mở máy B cùng tài khoản → thấy thay đổi.

6Chuyển người dùng sang

Dữ liệu trên máy (localStorage, PWA đã cài) gắn chặt với tên miền. Đổi tên miền = trình duyệt coi như web mới.

Giữ tên miền cũ (trỏ DNS về VPS)Tên miền mới (DuckDNS)
Tiến độ trên máyGiữ nguyên, PWA không cần cài lạiKhông thấy ở web mới
Người đã đăng nhậpVẫn đăng nhập (bảng sessions đã chuyển), app tự đồng bộĐăng nhập lại → tự kéo tiến độ từ server
Người chưa đăng nhậpKhông phải làm gìWeb cũ: tab Tôi → Tải backup → web mới: Khôi phục (gộp, không ghi đè)
Ghi sau lúc dumpKhông mất: máy người dùng còn bản gốc, lần đồng bộ sau tự gộp lên server mớiNằm lại ở Nhân Hòa; người dùng dùng Tải backup/Khôi phục như trên
Điều kiệnBạn quản lý DNS của tên miền đó (không phải tên miền tạm của Nhân Hòa)Không cần gì thêm

Khuyên dùng: giữ tên miền cũ nếu có thể. Khi đó ở chương 5 thay . bằng tên miền cũ, và:

  1. Trước 1 ngày: hạ TTL bản ghi DNS xuống 300 giây.
  2. Hôm chuyển: dump lần cuối (chương 3) → nạp lại (chương 4, docker compose stop app trước khi pg_restore --clean, xong docker compose start app).
  3. Đổi bản ghi A sang . Caddy tự xin chứng chỉ khi DNS trỏ đúng (có thể mất vài phút, Caddy tự thử lại).
Giữ Nhân Hòa chạy ≥ 7 ngàyĐể quay lại nếu có sự cố và để người dùng kịp tải backup. Sau đó xoá hẳn DB Nhân Hòa — nó vẫn giữ hash mật khẩu người dùng và mật khẩu sa đã từng lộ qua chat.

?Câu hỏi còn mở

  1. Nhân Hòa đang chạy PostgreSQL bản mấy? (quyết định image postgres:17 hay bản khác)
  2. Panel Nhân Hòa có nút tải backup, hoặc bật được cổng public tạm cho DB không? (chọn cách A hay B ở chương 3)
  3. Tên miền production hiện tại là gì, bạn có quản lý DNS của nó không? (quyết định giữ tên miền cũ hay chuyển sang DuckDNS)
  4. Repo LingoBrain public hay private? (private → cần deploy key)
