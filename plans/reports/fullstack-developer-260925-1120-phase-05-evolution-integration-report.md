## Issues Encountered / Deviations
- `boss-game-logic.js` (exactly 200 lines from phase 4) had zero line budget left; rather than touching it, `evoUltBonus`/`mageSprite` are set as plain properties on the `st` object returned by `createBattle`, read via `st.evoUltBonus || 0` / `st.mageSprite` in `combo-chain.js`/`sprite-actors.js`. This is backward compatible: any test or caller that builds a battle without setting these fields gets `undefined`, which behaves identically to "no evo form" (0 bonus, gender sprite).
- `js/boss-game-tier3-ultimate-fx.js` still hardcodes `ui.gender === 'm' ? 'mageMFace' : 'mageFFace'` for the ultimate cutscene faceset — NOT updated to use the evolved form's faceset. The assignment's scope explicitly named battle sprite, hub preview, and `boss-game-portrait-ui.js` faceset; the ultimate cutscene wasn't listed and touching it would need editing a file not in the assigned list without a clear budget check. Flagging as a known, intentionally out-of-scope gap (visually: cutscene face reverts to base gender face even mid-evolved-form battle).
- `bossEvoHasUpgrade` badge semantics: since `bossEvoUnlocked`'s level gate is GLOBAL (player level, not per-element rank), every element's forms unlock at the same levels 8/16 regardless of which element is active. Implemented as "current chosen form for the active element is below a level milestone the player has already reached" (0 = base) rather than a one-time "just reached" flag, because the `evo` schema has no room for a "seen" flag without violating the append-only sync contract mid-phase. This disappears once the player picks the highest form available, re-appears at 16 if they only picked the level-8 form — documented in the code comment. `bossEvoMilestoneReached` (result screen) is the precise "just crossed 8 or 16 this level-up" version and needed no such compromise.
- `docs/system-architecture.md` also received phase-4 (`skill-roster`/`skill-pick`/`skill-fx`/`skill-book-ui`) rows that were missing from before this session — phase 4's own report explicitly deferred docs to phase 5 per the plan's step ordering, so backfilling here avoids the module list silently going out of date.
